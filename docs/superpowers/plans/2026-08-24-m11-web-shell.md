# M11: The Web Shell — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A global, sidebar-driven shell in the handoff's visual language: a Projects list
with company assignment, a tabbed Agents surface over rosters and workers, a Settings page
managing the catalog through the M10 verbs, the four existing pages migrated onto a new
component library — plus the three M10 pre-tasks the UI builds on.

**Architecture:** Three control-layer pre-tasks first; then the token migration and a
presentational component library (`components/ui/`); then a pure org query module and thin
API routes in the goal/emergency-stop idiom; then the shell and three new pages; then the
four existing pages migrated one at a time; finally a Playwright-driven measured gate.

**Tech Stack:** Next.js (app router) + Tailwind v4 CSS variables, React 19, zod, Prisma,
vitest + testing-library, playwright-core for the gate.

**Spec:** `docs/superpowers/specs/2026-08-24-m11-web-shell-design.md`

## Global Constraints

- Full gate per task: `npm test && npm run typecheck && npm run web:build`.
- TDD per task: failing tests first, run to verify failure, implement, run green, commit.
- ONE vitest run at a time anywhere on the machine (shared test DB, TRUNCATE-per-file).
- Engine behavior is untouchable: no change to tick order, passes, guardrails, event ordering.
- `Workspace` keeps its name in code and storage; "Project" is UI copy only (spec §1).
- Existing page behavior is untouchable during migration: same semantics, same test-ids;
  the existing test suite must stay green unmodified except where a task says otherwise.
- Truth from snapshot: no optimistic rendering; mutations re-read (spec Decision 8).
- Motion sits behind `prefers-reduced-motion` (spec §3).
- Stage only the files the task names — never `git add -A` (unrelated untracked paths sit
  in the tree).
- Commit messages end with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- Line numbers cited below drift — locate by content.

```ts
export interface ProjectRow {
  readonly id: string; readonly name: string
  readonly companyName: string | null
  readonly halted: boolean
  readonly taskCounts: { readonly done: number; readonly total: number; readonly active: number; readonly blocked: number }
  readonly workerCount: number
  readonly spend: number            // sum of the workspace's run costs, same source as the budget bar
}
export async function listProjects(): Promise<readonly ProjectRow[]>

export interface RosterMemberRow {
  readonly companyAgentId: string; readonly name: string; readonly role: string
  readonly templateName: string
  readonly effectiveModel: string | null
  readonly modelSource: 'worker-varies' | 'roster' | 'template' | 'none'
  readonly rosterModel: string | null; readonly templateDefaultModel: string | null
  readonly workers: ReadonlyArray<{
    readonly agentId: string; readonly workspaceId: string; readonly projectName: string
    readonly status: string; readonly model: string | null
    readonly currentTask: { readonly title: string; readonly pct: number } | null
  }>
}
export interface RosterCompany {
  readonly companyId: string; readonly companyName: string
  readonly teams: ReadonlyArray<{ readonly companyTeamId: string; readonly teamName: string
    readonly members: readonly RosterMemberRow[] }>
}
export async function listRoster(): Promise<readonly RosterCompany[]>

export interface WorkerRow {
  readonly agentId: string; readonly name: string; readonly role: string
  readonly workspaceId: string; readonly projectName: string
  readonly status: string
  readonly currentTask: { readonly title: string; readonly pct: number } | null
}
export async function listWorkers(): Promise<readonly WorkerRow[]>   // company workers only (companyAgentId != null)

export async function listTemplates(): Promise<readonly {
  id: string; name: string; role: string; description: string; defaultModel: string | null }[]>
export async function listCompanies(): Promise<readonly { id: string; name: string }[]>
```

`modelSource`: `'roster'` when the roster row's model is set, else `'template'` when the
template default is set, else `'none'`; `'worker-varies'` when any worker overrides.
`effectiveModel` is the chain result ignoring worker overrides (each worker's own value
shows in its sub-row). Status and current task come from the same queries the existing
overview module uses — read `apps/web/src/server/overview.ts` first and reuse its
derivations rather than re-inventing them.
