# M7: Graph — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Graph page — Organization mode (live hierarchy with event-driven flow
visualization) and Dependencies mode (the task DAG with edge editing that the scheduler
already honours) — plus the dependency control operations behind it.

**Architecture:** One `GraphSnapshot` payload feeds both modes over the house liveness pattern
(`useWorkspaceStream`-based wake + refetch; raw SSE frames drive the flow effects directly).
Dependency writes go through `packages/control` with a cycle-refusing transactional claim.
React Flow renders both modes through one canvas; ELK lays out client-side (`mrtree` org,
`layered` deps); layout recomputes only when the node/edge set changes.

**Tech Stack:** TypeScript, Prisma/Postgres, Next.js 15 App Router, Tailwind v4, vitest +
testing-library, zod, `reactflow` + `elkjs` (the milestone's two new dependencies).

**Spec:** `docs/superpowers/specs/2026-08-22-m7-graph-design.md`

## Global Constraints

- Every web mutation goes through `packages/control`; `apps/web` never writes through Prisma
  (M5 §1). Reads unrestricted. `packages/control` never imports `packages/providers`.
- Control refusals map to HTTP 409 with `refusalText` as `{ error }`; route-level
  workspace/task mismatch is 404; malformed body is 400 (M5 §4 contract).
- The DAG can never acquire a cycle: `addTaskDependency`'s cycle check runs in the SAME
  transaction as the insert (spec §3.3). A dependency on a `done` task is allowed.
- `dependenciesDone` in the graph snapshot uses the scheduler's own `NOT EXISTS` semantics
  (`apps/orchestrator/src/world.ts:99-105`) — same definition, not a JS re-derivation.
- New event types `task.dependency_added` / `task.dependency_removed` extend the M6 exhaustive
  maps in the same task that adds them — `TYPES_BY_KIND` (kind `tasks`) and `ACTIVITY_CARDS`
  both fail compile until extended (spec §3.4).
- No optimistic UI: after any 2xx/409 the event-driven refetch is the truth; 409 text renders
  verbatim in the page's error band (spec §4.5).
- Every movement carries information (parent §12.1): particles fire one-per-event with a
  per-edge cap (~5) and pause while the tab is hidden; all motion behind `motion-safe:`;
  under reduced motion particles do not render at all; no springs; no new colour tokens.
- Layout recomputes only when the node/edge SET changes — a status change repaints, never
  re-layouts (spec §4.2).
- The M4-protected `apps/web/test/useOverview.test.tsx` original tests stay untouched.
- Tests: TDD; unit under `apps/web/test/` (and package test dirs), integration (real
  Postgres, port 5433) under `<pkg>/test/integration/`.
- **Every task's full gate: `npm test && npm run typecheck && npm run web:build`.**
- Commits: conventional prefixes as in the log.

```ts
  taskId: string, dependsOnTaskId: string, requestedBy: string,
): Promise<Result<void, ControlRefusal>>

  taskId: string, dependsOnTaskId: string, requestedBy: string,
): Promise<Result<void, ControlRefusal>>
```

`ControlRefusal` gains:

```ts
| { readonly kind: 'task_not_found'; readonly taskId: string }
| { readonly kind: 'self_dependency'; readonly taskId: string }
| { readonly kind: 'duplicate_dependency'; readonly taskId: string; readonly dependsOnTaskId: string }
| { readonly kind: 'cross_workspace'; readonly taskId: string; readonly dependsOnTaskId: string }
| { readonly kind: 'dependency_not_found'; readonly taskId: string; readonly dependsOnTaskId: string }
| { readonly kind: 'dependency_cycle'; readonly taskId: string; readonly dependsOnTaskId: string }
```

with `refusalText` cases (one readable sentence each; the cycle one:
`` `adding this dependency would create a cycle: ${dependsOnTaskId} already depends on ${taskId}` ``).

- [ ] **Step 1: Failing integration tests** — seed a workspace + tasks; cases: happy add
  (row exists, `task.dependency_added` appended with title+requestedBy), self → refused,
  duplicate → refused, cross-workspace → refused, unknown task → refused, chain A→B→C standing
  then C depends-on A **refused as `dependency_cycle`** (and the direct 2-cycle B→A too),
  dependency on a `done` task → allowed, happy remove (row gone, event appended), remove
  non-existent → `dependency_not_found`.
- [ ] **Step 2: Run to verify failure**, then implement. `addTaskDependency`: read both tasks
  (+ workspace equality) → refusals; then `prisma.$transaction` — inside it, the cycle check as
  a recursive CTE:

```sql
WITH RECURSIVE reach(id) AS (
  SELECT "dependsOnTaskId" FROM "TaskDependency" WHERE "taskId" = ${dependsOnTaskId}
  UNION
  SELECT td."dependsOnTaskId" FROM "TaskDependency" td JOIN reach r ON td."taskId" = r.id
)
SELECT 1 FROM reach WHERE id = ${taskId} LIMIT 1
```

plus the trivial direct check (`dependsOnTaskId`'s own row set already covers it via the seed
row of the CTE — verify with the 2-cycle test); reachable → refuse `dependency_cycle`; else
`create` (unique violation → `duplicate_dependency`, or pre-check — pick one and test it) and
`appendEvent` in the same transaction. `removeTaskDependency`: `deleteMany` conditioned on
both ids; zero rows → `dependency_not_found`; else append the removed event.
- [ ] **Step 3: Full gate.**
- [ ] **Step 4: Commit**

```ts
export interface GraphAgent {
  readonly id: string; readonly name: string; readonly role: string
  readonly teamId: string

  readonly activeTaskId: string | null
  readonly activeTaskTitle: string | null

export interface GraphTask {
  readonly id: string; readonly title: string
  readonly status: TaskStatus
  readonly priority: number
  readonly attempt: number; readonly maxAttempts: number
  readonly dependenciesDone: boolean
}
export interface GraphSnapshot {
  readonly workspace: { readonly id: string; readonly name: string; readonly haltedReason: string | null }

export function useGraph(workspaceId: string, initial: GraphSnapshot): {
```
