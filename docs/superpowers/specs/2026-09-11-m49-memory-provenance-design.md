# M49 — Organisational memory with provenance

Sixth milestone of the roadmap `2026-09-10-roadmap-m44-m56.md`, on M48's contracts and runbooks. Designed 2026-09-11 from an inventory of the run-context manifest, verify/review/merge outcomes, the decision record, the existing provenance shapes and the project surfaces (session scratchpad `m49-explore.md`). Every **Ruling** took the recommended option under the user's standing approval. "Slave" is this project's word for an AI worker.

**Goal.** What the organisation learns is kept as knowledge with provenance, not as a transcript: a worker's output becomes an OBSERVATION candidate, a passed verification turns it into a verified FACT, a human's decision (approving or rejecting a proposal, changing the goal) becomes a DECISION, a review or verify failure becomes a LESSON for the worker that made it. Every memory says where it came from (source, creator, task, run, goal version), how sure we are, who verified it, and what replaced it. A run is given the verified knowledge that matches its scope and references, deterministically, and its manifest records exactly which memories it received. Summaries condense many memories into one that points back at its sources; nothing is ever deleted, only superseded or removed-with-a-reason. The page shows knowledge — filtered by scope, type and status, with its provenance — and lets a person verify, correct or remove it.

**Facts the design stands on.** No `memory`/`knowledge`/`lesson`/`provenance` name exists in the repo; the closest shapes are M39's `Source { kind, ref, quote }` with `verifySources`, M42's `ProfileSource`, the manifest sha256s, `Slave.selectionRationale`, and `SlaveMessage.supersededAt` (stamped, never deleted). A worker's final text lives only in `run.output` events (`concludeReview` reassembles it). `Task.lastRejectionReason` is written by one function (`rejectTask`). Decisions are resolved in three control functions (`approveDecision`, `rejectDecision`, `resolveSettledDecisions`) and goals change in `setGoal`/`requestChange`. The run manifest is READ-tolerant / WRITE-strict; a new section kind gets a REQUIRED-field source. `gate:m44`'s RAW_TOKENS blocklists union members with `_` or `.`; bare words are not blocklisted but the IA rule still demands labels. Confidence vocabulary already exists: `'sourced' | 'interpretation'`.

## 1. Rulings
- **R1 — One table, `Memory`, with typed provenance columns.** `type MemoryType` = `fact | decision | procedure | lesson | observation | hypothesis`; `scope MemoryScope` = `company | workspace | worker` with exactly one target FK non-null (`companyId`, `workspaceId`, `slaveId`; all `onDelete: Cascade`); `title` (≤ 120), `body` (≤ 2000); `status MemoryStatus` = `candidate | verified | superseded | removed`; `confidence` = `sourced | interpretation` (M39's words); provenance: `sourceKind MemorySourceKind` = `run_output | verification | review | decision | goal | human | condensation`, `sourceRef String?` (event seq, decision id, goal version… as text), `createdBy Actor`, `createdByUserId?`, `taskId?` (SET NULL), `runId?` (SET NULL), `goalVersion Int?`, `capabilities String[]` (retrieval references, taxonomy keys), `verifiedAt?`, `verifiedBy String?` (`verification | review | human`), `supersededById?` (self-FK, SET NULL), `removedReason String?`, `createdAt`, `updatedAt`. `MemorySource { memoryId, sourceMemoryId }` (`@@id`) links a condensation to what it summarises. Domain `packages/domain/src/memory/{types,provenance,promote,retrieve,condense}.ts`: `MEMORY_TYPES/SCOPES/STATUSES/SOURCE_KINDS` + labels (`MEMORY_TYPE_LABEL` …), `memorySchema` (`.strict()`, caps), `MemoryView` (no `Date`, ISO strings), pure helpers. Nothing is backfilled.
- **R2 — Promotion is a pure rule applied at four hooks, enforced by one control verb.** `promotionFor(input): MemoryDraft | null` in the domain decides, from a small typed input, what to write: (a) an implementation run **succeeds** → OBSERVATION `candidate` (scope workspace; body = the run's final assistant text capped at 2000 code points, title = `Task: <title>`; `sourceKind run_output`, `sourceRef` = the last `run.output` event seq, `confidence interpretation`, `capabilities` = the task's `requiredCapabilities`); (b) `task.verify_passed` → FACT `verified` (`verifiedBy verification`, `sourceKind verification`, body = the task's handoff `expectedOutput` when present else `<title> — verified by <commands>`; the task's latest OBSERVATION candidate gets `supersededById` = the fact, status `superseded`; `confidence sourced`); (c) a human resolves a decision (`approveDecision` / `rejectDecision`) or the goal changes (`setGoal` v ≥ 2, `requestChange`) → DECISION `verified` (`verifiedBy human`, `sourceKind decision | goal`, body = the decision's rationale + outcome, or the goal request/diff sentence; `createdBy human`); (d) `task.review_rejected` / `task.verify_failed` → LESSON `verified` scoped to the **worker** that did the run (`slaveId` = the run's slave; body = the rejection reason capped; `sourceKind review | verification`; `confidence sourced`). PROCEDURE and HYPOTHESIS are never promoted automatically in M49 (a person writes them; condensation may produce a PROCEDURE from LESSONs — R5). The control verb `recordMemory(draft, principal?)` validates, writes, appends `memory.recorded`; the four hooks call it from the code that already owns the outcome (`advance`, `concludeReview`, `verify`'s `rejectTask` callers, the three decision resolvers, `setGoal`/`requestChange`), never from the pump. **The Supervisor suggests:** situation `memory_candidates_piling` (14th; subject = workspace; fires when ≥ 5 OBSERVATION candidates are older than `MEMORY_CANDIDATE_STALE_MS` = 24 h) with one offer `discard_stale_candidates { workspaceId, count }` (14th action, tier `proposed`; `carryOut` marks them `removed` with reason `stale candidate, never verified`) then `escalate_to_human`.
- **R3 — Retrieval is deterministic and a run's manifest records it.** `retrieveMemories(input: { memories: MemoryView[]; scopes: { companyId?, workspaceId, slaveId? }; refs: { taskId?, requiredCapabilities, goalVersion? }; kind: 'implementation' | 'planning'; limit })` (pure): eligible = status `verified` only (candidates and superseded never reach a prompt), scope ∈ the run's company/workspace/worker; excluded = the sources of an included condensation; ranking = scope specificity (worker > workspace > company) → type order (`decision, fact, procedure, lesson, observation, hypothesis`) → capability overlap with `refs.requiredCapabilities` desc → same `taskId` first → `createdAt` desc → id asc; `MEMORIES_IN_PROMPT` = 12; LESSONs only for the running worker's own scope. Control `memoriesForRun(runId-ish input)` loads the three scopes in one query (bounded `MEMORIES_LOADED_MAX` = 500, `orderBy createdAt desc, id asc`) and calls the pure function. New `SectionKind` `memory` (source `{ kind: 'memory'; memoryIds: string[]; capped: boolean }`, REQUIRED fields) rendered after `handoff` on `implementation` and after `handoff_protocol` on `planning` (not on `review`); heading `WHAT THE ORGANISATION KNOWS`, one block per memory (`[FACT · verified by verification · task <title>] <title>: <body>`), every string through `defuseRoutingLiterals(neutraliseMarkers(singleLine(…)))`; null when nothing qualifies; `runContextSummary` prints the count. `show-context` shows it for free.
- **R4 — Correct, verify, remove, supersede — by people, with events.** Control verbs: `addMemory` (any type/scope, `createdBy human`, `sourceKind human`, status `verified`), `verifyMemory` (candidate → verified, `verifiedBy human`), `supersedeMemory(oldId, { title, body })` (new verified memory with the old's provenance copied + `sourceRef old id`; old → `superseded`, `supersededById` set), `removeMemory(id, reason)` (status `removed`, reason kept; a removed memory stays in the table), `listMemories(filter)` (scope, type, status, taskId, capability; key-stable ordering), `readMemory(id)` with its chain (what it superseded, what superseded it, its condensation sources). Refusals: `memory_not_found` (404), `invalid_memory` (409), `memory_not_editable` (409: removed/superseded rows are frozen). Events: `memory.recorded { memoryId, type, scope, status, sourceKind, taskId? }` (51st; lane `verified` via `laneFor` when status is `verified`, else no lane) and `memory.changed { memoryId, from, to, reason? }` (52nd; lane `decision` when a human did it). Every write goes through `appendEvent` after its transaction.
- **R5 — Condensation is deterministic and keeps every source (last task; may split into M49b).** `condenseMemories(memories, { scope, type, threshold })` (pure): when a scope holds ≥ `CONDENSE_THRESHOLD` (20) verified memories of one type that are not already sources of a live condensation, produce ONE memory of the same type, `sourceKind condensation`, `confidence sourced`, title `<Type> summary (<n> sources, <date range>)`, body = the sources' titles as a deterministic bullet list (sorted `createdAt asc`), capped at 2000 code points with a `… and N more` tail, `capabilities` = the union; the sources stay `verified` (a summary is an index, not a replacement); `MemorySource` rows link them. Retrieval prefers the summary and excludes its sources (R3). Control `condenseWorkspaceMemories(workspaceId, type?)`; CLI `memories condense`; the Supervisor does NOT trigger it in M49 (a person or a cron does). Special case ruled in: condensing LESSONs of a worker yields a PROCEDURE ("what this worker has learned to do") — the one automatic PROCEDURE.
- **R6 — Surfaces: a Knowledge page, and provenance where the work is.** Project tab `Knowledge` (`/w/:id/knowledge`, sixth tab between Organization and Activity; the two tab-strip pins and `docs/ia.md` move): filters by scope (company / this project / a worker), type, status (verified / candidates / superseded / removed — default verified + candidates), a search box on title; rows = type chip (label) · title · scope · provenance line ("from a passed verification of *Ship the checkout API* · run 3f2a · goal v2 · verified by verification") · confidence · actions **Verify** (candidates), **Correct** (opens a drawer with title/body → supersede), **Remove** (with reason, `DangerConfirm`); a row expands (`DetailsGroup group="provenance"`, new name) to the chain (superseded by / supersedes / condensation sources with links) and the raw values in `title`/`data-` attributes. Task drawer: `DetailsGroup group="memories"` (new name) listing what the task's runs **received** (from the manifests) and **produced** (memories with `taskId`). Overview brief: one line `Knowledge: N verified · M candidates` linking to the tab (no panel). Routes: `GET /api/w/:id/memories?scope&type&status&q`, `POST /api/w/:id/memories`, `POST /api/w/:id/memories/:mid/verify | supersede | remove`. CLI `memories list|add|verify|supersede|remove|condense`. Copy prints labels; keys only in `title`/`data-`; `gate:m44` RAW_TOKENS gains the four memory unions.
- **R7 — Gate.** `gate:m49-memory` (real daemon + fake CLI + Playwright): a workspace with a goal and one worker; `plan-graph-runbook`-style planning with contracts; task 1's work run succeeds → one OBSERVATION candidate with `runId`, `taskId`, `sourceRef` = the last `run.output` seq, body = the fixture's final assistant text; verify passes → a FACT `verified by verification` whose body is the contract's `expectedOutput`, the candidate now `superseded` pointing at it; task 2's review is answered from `review-reject` → a LESSON scoped to the worker with the fixture's reason; a human approves a pending proposal via the real CLI → a DECISION with the rationale; the NEXT implementation run's recorded manifest carries `memory` with exactly the FACT + DECISION ids (not the candidate, not another worker's LESSON — assert the negative), its prompt has the heading; `memories supersede` by CLI → chain of two, retrieval now yields the new one only; a seeded batch of 20 FACTs → `memories condense` → one summary with 20 `MemorySource` rows, the next run receives the summary and none of the 20; the Knowledge page in a real browser: filters, the provenance line, the chain in the expanded row, Correct and Remove round-trips; the task drawer's memories group; six project PNGs move with the sixth tab (regenerated once). README roster 23 → 24; CI step after `gate:m48-runbooks`.
- **Never a real model call (condensation is deterministic text, no model); one vitest at a time; `web:build` last, never beside `next dev`; vocabulary `slave`; migrations additive with the Prisma 7 diff proof; `decide()` unchanged; the M47/M48 gates unchanged; a refusal after a write inside a transaction throws; refusal kinds in three homes; labels never keys.**

## 3. Out of scope
Embeddings or any semantic retrieval; model-written summaries; workers editing memories from a run; cross-company sharing; permissions on memories (M52); evidence-based ranking (M53); automatic PROCEDURE/HYPOTHESIS promotion beyond R5's one case; retention/expiry.
