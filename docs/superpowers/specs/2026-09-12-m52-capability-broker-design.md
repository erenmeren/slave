# M52 — Default-deny capability broker

Ninth milestone of the roadmap `2026-09-10-roadmap-m44-m56.md`, extending `SlavePermission` (M11), the M18 hook permission path (`scripts/pause-gate.sh`, `scripts/lib/permissions.sh`, `writePermissionsFile`) and `buildChildEnv` — named as extensions, per roadmap lines 19-23 and 57. Designed 2026-09-12 from an inventory of the permission model and its one writer, the two hook gates and their measured exit contract, the five nouns and the three meanings of "capability", worker identity, the Supervisor's tier table, the simulation boundary, the UI and the gates that pin all of it (session scratchpad `m52-explore.md`), with findings — never shapes — borrowed from `munder-difflin`'s integration broker and `agency-agents`' tool manifests. Every **Ruling** took the controller's direction under the user's standing approval; where the repository forces a different shape the ruling carries an inline `(verified: …)` note. "Slave" is this project's word for an AI worker.

**Goal.** A worker may do exactly what someone decided it may do, and nothing else. The gate stops asking "is this forbidden" and starts asking "is this allowed": an absent, stale or unreadable matrix denies, an ungoverned tool denies, a forged identity denies. A worker never holds a credential — it asks the orchestrator, by name, for one of a closed list of operations with typed parameters, and the orchestrator runs it in its own process with the secret the worker cannot see, recording what was asked and what happened. Identity stops being a path: every run carries a token issued at spawn, hashed on the row, and the verdict a gate reads is bound to it. The Supervisor may point at a wall; only a person moves it.

**Facts the design stands on.** `SlavePermission {id, slaveId, tool String, mode PermissionMode}` (`schema.prisma:539-548`) has one writer — `setSlavePermission` (`packages/control/src/permission.ts:96-118`), no delete verb, no CLI verb, no seed rows — and four readers that each do `writePermissionsFile(runDir, resolveDenyList(rows, provider))` (`tick.ts:665`, `planning.ts:535`, `review.ts:484`, `resume.ts:84`). `resolveDenyList` skips everything but `deny` (`permission.ts:53`) and `read_permission_verdict` treats an absent file as "no matrix in play: allow" (`scripts/lib/permissions.sh:91-93`) — default-ALLOW twice over, over six prose rows (`PERMISSION_TOOLS`, `permission.ts:18-26`) of which three collapse to `Bash` and one (`read secrets`) maps to nothing. `claudeFlags` hardcodes `--permission-mode bypassPermissions` (`flags.ts:35-40`), so the hook is the only gate; M3 measured that exit 2 fails CLOSED while 1/126/127 fail OPEN, and that a deny is carried in a JSON body at exit 0 (`scripts/pause-gate.sh:6-24`). One `node -e` per tool call reads payload and file in the same process (`permissions.sh:51-55`). `runDir = join(repoPath,'.slaveofai','runs',runId)` (`packages/control/src/paths.ts:33`) is inside the repository the worker edits, and the library records the self-policing hole in its own comment (`permissions.sh:57-59`). `buildChildEnv` spreads `...process.env` (`runtime/process.ts:157-165`); there is no credential model, no `SLAVEOFAI_RUN_ID`, and nothing binds a verdict to a slave. `RunKind {implementation, review, planning}` (`schema.prisma:593-597`) is closed; `Slave.runtimeRoles` is free text capped at `MAX_RUNTIME_ROLES = 20`. `tierOf` demotes everything under a halt (`policy.ts:47`) and `assign_capability` is `applied` (`:69-70`). The event catalogue holds 55 types (`packages/db/src/enums.ts:10-64`). `scripts/gate-fakes/` already holds three fakes; the gate roster ends at `gate:m51-breaker` with "26 gates" (`README.md:908`, `package.json:64`).

## 1. Rulings

- **R1 — Five nouns, five homes, and a permission is an OPERATION, never a capability.** CAPABILITY stays M47's taxonomy — what a worker is FOR (`Capability`, `Slave.capabilities[]`, `Task.requiredCapabilities`, `assign_capability`), untouched. SKILL stays the catalogue plus the pump's tally. PROFILE stays M46's `ProfileSpec`, whose `constraints[]` is prose the model reads and is explicitly NOT enforcement. PERMISSION becomes a closed vocabulary of OPERATIONS in `packages/domain/src/permission/kinds.ts`: `PERMISSION_KINDS = ['read_repo','write_repo','run_commands','network_fetch','read_secret','deploy_release']` with `PERMISSION_LABEL` (`Read the repository` / `Write source` / `Run commands` / `Fetch over the network` / `Read a secret` / `Deploy a release`), `PermissionKind`, and `TOOLS_BY_KIND: Record<PermissionKind, Record<ProviderKind, readonly string[]>>` — the inverted `CAPABILITY_TOOLS` (`permission.ts:39-46`), now naming the FULL governed toolbox per kind (`read_repo` → `Read`, `Glob`, `Grep`, `NotebookRead`, `TodoWrite`, `Task`, `Skill` / `read`; `write_repo` → `Write`, `Edit`, `NotebookEdit` / `edit`; `run_commands` → `Bash`, `BashOutput`, `KillShell` / `shell`; `network_fetch` → `WebFetch`, `WebSearch` / nothing; `read_secret` and `deploy_release` name NO vendor tool — they are broker grants only, which is exactly why `deploy prod` could never be expressed as a tool deny). `TOOL_VOCABULARY` is the per-provider union, pinned by `packages/domain/test/permission/kinds.test.ts` against the tool names the fixtures observe, so a vendor tool nobody mapped is a red test and not a silent hole. `SlavePermission.tool` becomes `kind PermissionKind` and gains `grantedBy String?` / `grantedAt DateTime @default(now())`; `@@unique([slaveId, kind])` replaces `@@unique([slaveId, tool])`. Migration `20260912180000_m52_broker`: add `kind` nullable → one deterministic `UPDATE` (`repo read`→`read_repo`, `source write`→`write_repo`, `run tests`/`create branch`→`run_commands` with **deny wins** on the collision and the redundant row deleted, `deploy prod`→`deploy_release`, `read secrets`→`read_secret`) → `DELETE` every unmapped row with `RAISE NOTICE 'm52: dropped % unmapped permission rows'` (dropped, not kept under an `other`: the column is a bare `String` with no check constraint, and under default-deny a dropped row denies, which is the safe direction, while an `other` kind would invent a grant nobody can name) → `SET NOT NULL` → drop `tool` and its index → add the new unique. *(verified: `read secrets` is not deleted for being "a lie" (`permission.ts:45`, `PermissionMatrix.tsx:84`) — R3 gives it teeth as the credential gate, which answers the inventory's Q7.)* **Answering Q15 explicitly: kept apart.** Permissions and capabilities never unify — a taxonomy key says what a worker is dispatched FOR, a permission kind says what any worker MAY DO, and the UI prints "Permissions" and "Capabilities" as two words for two things, never one for both. `enum PermissionMode {allow, deny}` survives unchanged with a sharper meaning: `allow` is a grant, `deny` is a person's explicit refusal, and ABSENCE is "never asked" — all three deny at the gate, and the three states are what `PermissionMatrix`'s ✓/✕/– glyphs (`PermissionMatrix.tsx:9-23,124-140`) have always drawn. *(verified: keeping `mode` rather than making the row a bare grant preserves the existing three-glyph vocabulary, keeps `flip()` (`:49-53`) honest for the first time, and spares `invalid_permission_mode` a retirement across its three refusal homes.)*

- **R2 — Default-deny, everywhere the gate looks, and the baseline is computed rather than stored.** `resolveDenyList` becomes `resolveGrants(rows, provider, runKind)` in `packages/control/src/permission.ts`, returning the ALLOWED vendor tools; `writePermissionsFile` writes `{"version":2,"runId":"…","tokenHash":"…","allow":[{"tool":"Read","kind":"read_repo"}]}`. - **R4 — Worker identity comes from the runtime context, and the verdict a gate reads moves out of the worker's reach.** `SlaveRun.runTokenHash String? @unique` — `sha256` hex of 32 random bytes issued at spawn at the four dispatch sites and ROTATED on every resume, so a token recovered from an old worktree is dead. The plaintext exists only in the child's environment: `SLAVEOFAI_RUN_ID` and `SLAVEOFAI_RUN_TOKEN`, added to `CHILD_ENV_ALLOW`'s explicit list and to `buildChildEnv`'s required inputs. Both the hook and the broker resolve run → slave from the token and nothing else; the broker compares with `timingSafeEqual` over the hashes, and a mismatch, an unknown token or a concluded run is `identity_mismatch`, which fails closed. The hook needs no database and no second spawn: `permissions.json` carries `tokenHash`, and the node process already reading the file compares it to `sha256(SLAVEOFAI_RUN_TOKEN)` — which closes the "point `SLAVEOFAI_PERMISSIONS_FILE` at a sibling run's file" hole, because a sibling's hash will not match this child's token. `runFilePaths` (`packages/control/src/paths.ts:33`) moves `runDir` out of the worktree to `<SLAVEOFAI_STATE_DIR ?? $XDG_STATE_HOME ?? ~/.local/state>/slaveofai/runs/<runId>`, created `0700`; the pause flag, the permissions file, the tool-results tap and the broker channel all move with it, both adapters keep re-deriving the path from `dirname(checkpoint.pauseFlagPath)` unchanged, and a pre-M52 `Checkpoint` resumes against its old absolute path with no migration. `.slaveofai/` stops being written into a repository at all, which retires the self-policing threat model comment (`permissions.sh:57-59`) instead of restating it: a worker can no longer delete the file that governs it, because it can no longer see it. Cursor's `.cursor/hooks.json` stays in the worktree — it is the vendor's required location — and remains a stated limitation.
