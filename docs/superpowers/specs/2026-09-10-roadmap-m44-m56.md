# Roadmap M44–M56 — an evidence-driven AI organisation, seen through one Supervisor

Written 2026-09-10 after M42 merged (main = 985e5ff). This is the user's direction prompt, revised
where the repository already answers it or where the prompt would have fought the repository. The
repository is the source of truth; this document is the ORDER and the SCOPE. Each milestone gets its
own spec (`docs/superpowers/specs/`), plan, subagent-driven execution, final review, local merge; a
push happens on the user's word. "Slave" is this project's word for an AI worker.

## Rules that apply to every milestone (added to the prompt)
- **Vocabulary.** The product word is `slave`; `gate:m26-vocabulary` forbids the other word in
  every tracked file outside `docs/superpowers`, `docs/decisions`, migrations and fake-CLI fixtures.
  The prompt's example states (`waiting_for_agent`) and copy are rewritten in the repo's words.
- **No real model call** in tests or gates (`packages/providers/test/fake-claude.mjs`,
  `SLAVEOFAI_REQUIRE_FAKE_CLI=1`). A real call needs the user's explicit consent, per call.
- **Every milestone ships a gate** (`scripts/gate-mNN-*.mjs`, CI, README roster) that proves its
  claim under a real daemon with the fake CLI. A UI milestone also regenerates the
  `gate:m14-fidelity` screenshots in a deliberate commit.
- **Extend, do not rewrite.** The prompt's concepts map onto existing subsystems; each spec names
  the subsystem it extends: profile chain (M37), run context + manifest (M37), Supervisor decision
  record and mailbox (M38/M39), requirement versions and delta re-plan (M40), catalog import with
  provenance and `locally_edited` (M42), guardrails and `workspaceStats` (M8/M32/M38),
  `SlavePermission` (M11), `Task.integratedAt` (M35), simulation → compare → adopt (M29–M33),
  `SlaveRuntimeAdapter` (M12/M13), the single event write gate (ADR 0003).
- **Backend state fidelity is never weakened for the UI.** User-facing status is a projection
  (`packages/domain`), inspectable down to the internal value.
- **Real project ≠ simulation** — separate routes, labels, colours and money (simulated money is
  never shown beside model cost).
- **Migrations are additive and applied to both databases;** Prisma 7 diff proof (spec M42 E23).
- **Third-party content.** Persona catalogs are imported from a user-supplied checkout and never
  vendored by default; a THIRD_PARTY notice is added only if content is shipped with the product.

## What changed from the prompt, and why
- **M44 split into M44 (foundation) and M45 (project/Supervisor experience)**; everything after
  shifts by one (prompt M45 → M46 … prompt M55 → M56). One UI milestone that also redesigns the
  project page would have been two milestones' work with one review.
- **Vocabulary and fake-CLI rules made explicit** (above) — they are repository gates.
- **Capability ↔ runtime role** is a decision the M47 spec must make, not a parallel system.
- **Memory retrieval is deterministic in v1** and condensation is last/optional (M49).
- **Circuit breaker and capability broker are extensions** of existing guardrails and
  `SlavePermission`, named as such; the hook event plane is a bounded spike inside M51.
- **Provider contract** builds on the existing adapter interface; provider breadth stays last.
- **Third-party notices** only when content is vendored; the M42 importer already keeps
  source/sha/licence-free provenance and the user's own checkout.
- **Measurement**: each milestone's gate is its acceptance criterion; UI milestones refresh the
  fidelity screenshots; the "ten seconds" target becomes an M45 gate on a fixed scenario.
