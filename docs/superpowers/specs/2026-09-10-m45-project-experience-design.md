# M45 — UX foundation B: the project as one Supervisor experience

Second milestone of the roadmap `2026-09-10-roadmap-m44-m56.md`, on M44's navigation, primitives and status projection. Designed 2026-09-10 from an inventory of the Overview, Supervisor, goal/re-plan, evidence, cost, messaging, task/worker and event surfaces (session scratchpad). Every **Ruling** took the recommended option under the user's standing approval. "Slave" is this project's word for an AI worker.

**Goal.** When a user opens a project they understand it in about ten seconds and they talk to ONE Supervisor: the Overview becomes a brief (objective, Supervisor state, current work, team, needs-you, latest verified result, actual cost, recent changes) above a Supervisor timeline whose entries are organisational events in six lanes — USER REQUEST · SUPERVISOR INTERPRETATION · PLAN CHANGE · WORK IN PROGRESS · DECISION REQUIRED · VERIFIED RESULT — with the decisions a human must take answerable in place, and a single input to tell the Supervisor what changed. Task and worker rows disclose progressively. No new autonomy: every mutation goes through the existing verbs (M38/M39 decisions, M36 answers, M40 goal versions + delta re-plan); the Supervisor's "interpretation" is what the system can honestly say — the delta it produced — not a new model call.

## 1. Rulings
- **R1 — The brief is a projection, not a dashboard.** `buildProjectBrief(workspaceId)` (`apps/web/src/server/brief.ts`) returns exactly ten facts from reads `overview.ts` already makes plus three new projections: `objective { text, version }`; `supervisor { state, label }` (new domain `userSupervisorStatus(report, workspace)` in `packages/domain/src/status/user.ts`: OFF / HALTED, NEEDS YOU / N DECISIONS WAITING / ANSWERING / WORKING / WATCHING / IDLE — precedence halted > off > pending decisions > unanswered questions > active work > idle); `work { working, verifying, review, waiting, done }` via `userTaskStatus`; `team [{ slaveId, name, roleLabel, status (projected), taskTitle }]` (kind PERMANENT/PROJECT is M50 — a `company` marker where `companySlaveId` is set); `needsYou [{ kind: 'blocked_task' | 'decision' | 'question' | 'integrate', title, href, since }]` (new `buildNeedsYou` through the domain `needsYou()` — blocked tasks, pending human decisions, questions no slave can answer, un-integrated done on a hand-merge workspace); `latestVerified { taskTitle, kind: 'integrated' | 'approved' | 'verified', at } | null` (most recent `task.integrated`, else `task.review_approved`, else `task.verify_passed` event); `cost { measuredUsd, unmeasuredCalls, budgetUsd }` (the M32 two-part figure; the three-tier split is M51 — the UI says "measured" and "N unmeasured calls charged at the cap", never one number); `recentChanges [{ at, summary }]` (last six events of the `workspace.*`, `org.changed`, `slave.profile_changed`, `slave.runtime_roles_changed`, `supervisor.applied/approved` families through `readableEventType`). Why: every fact exists or is a projection; cost if wrong: a field.
- **R2 — The Supervisor timeline is events + decisions classified into six lanes, deterministically.** `packages/domain/src/supervisor/timeline.ts`: `laneFor(entry)` where entries are `ExecutionEvent`s and `SupervisorDecision`s: USER REQUEST = `workspace.goal_set` (with the request words, R3) and human `task.created`/`cancel-task`; SUPERVISOR INTERPRETATION = `workspace.replan_started` ("reading the change to v{n}") and `workspace.replanned` rendered as "understood v{n}: +{added titles}; proposes cancelling {titles}; {n} kept" (no new stored sentence — the delta IS the interpretation; a re-plan that added nothing says so); PLAN CHANGE = `task.created` with a `goalVersion` > 1 or from a planning run, `task.cancelled`, `workspace.plan_created`; WORK IN PROGRESS = `task.started`, `task.verifying`, `task.review_started`, `run.paused`/`resumed`, `slave.message_sent` (collapsed: the lane shows the latest per task, with "+N earlier" disclosure); DECISION REQUIRED = pending `SupervisorDecision` rows (proposed/escalated), questions addressed to nobody or awaiting a human, blocked tasks — each with its existing inline action (`ProposalRow`/`DraftEditor` approve-with-edit/reject, answer input → `/messages/:id/answer`, unblock); VERIFIED RESULT = `task.verify_passed`, `task.review_approved`, `task.done`, `task.integrated`. `run.output`/`run.tool_call` never appear (model chatter). `buildSupervisorTimeline(workspaceId, { limit })` in `apps/web/src/server/timeline.ts` merges by time, newest first, and is refreshed by the existing SSE stream. Why: the prompt's six lanes map one-to-one onto events the system already writes; cost if wrong: a classification table.
- **R3 — "Tell the Supervisor" writes a goal version with the request words kept.** One input on the Overview (`supervisor-request`): `requestChange(workspaceId, request, by)` in `packages/control/src/goal.ts` composes the next goal text by the pure `composeGoal(previous, request, at)` (`packages/domain/src/goal/compose.ts`: the goal document keeps its body and gains a dated `Requested changes` list entry — idempotent formatting, byte-stable), calls `setGoal`, and stores the words: **one additive migration** `GoalVersion.request String?` + `workspace.goal_set.payload.request?` (optional; old rows null). M40's trigger then re-plans as a delta, and the timeline shows USER REQUEST (the words) → SUPERVISOR INTERPRETATION (`replan_started`, then `replanned`) → PLAN CHANGE → DECISION REQUIRED (proposed cancellations). CLI: `request-change --workspace <id> --request "…" [--by]`. "Bring in a security specialist" is M47/M50 — until then the request lands in the goal and the re-plan may add a task; the timeline never pretends otherwise. Why: the only honest path from a sentence to a plan today is a goal version; cost if wrong: a column and a verb.
- **R4 — Progressive disclosure.** Task row = projected word · title · who · one-line "why" (blocked reason / waiting for / rework reason); expanded = the existing `TaskDetailPanel` content reorganised under `Details ▾` groups (Run · Model · Profile · Skills · Messages · Context sources · Verification attempts · Cost · Worktree · Events) — raw statuses, ids, hashes only inside groups, in `title`/mono. Worker row = projected word · name · role label · current task; expanded = `SlavePanel` under the same groups. No new data; existing routes (`/runs/:id/context`, artifacts) feed the groups lazily. `Advanced ▾` keeps Graph, Office, Analytics.
- **R5 — `PageShell` for `/w/:id/*` (M44 E25) and the four global pages**, pixel-neutral where the fidelity gate asserts numbers; Office stays as is inside the shell.
- **R6 — Real vs simulation stays separate:** nothing from `/sim` renders in the brief or timeline; `adoptedFrom` stays an info line.
- **R7 — The gate.** `gate:m45-project-experience` (Playwright, no daemon, like m44): seeds a fixed scenario through control verbs and Prisma (goal v2 with a request, tasks in seven states, one pending `stale_task` proposal, one question to nobody, one integrated task, one un-integrated done task on hand-merge, one failed run, spend), then asserts at 1440×900: the ten facts render inside the first viewport with the expected words; the timeline shows the six lanes with the seeded entries in the right lanes and no `run.*` chatter; the needs-you list has exactly four entries with working links; approving the proposal from the timeline cancels the task and the lane updates; "Tell the Supervisor" creates goal v3 with the words stored and `replan-status` says `willReplan true`; task row → Details discloses the raw values only inside groups; `data-simulation` never appears on the page. `gate:m14-fidelity` page set gains nothing (Overview/Tasks already in it); screenshots regenerate in their own commit; m11-shell's Overview selectors are repointed. README `## One Supervisor` section + roster 19 → 20; CI.
- **Never a real model call; one vitest at a time; `web:build` last, never beside `next dev`; vocabulary `slave`; no removal — the old Overview panels' facts all live in the brief/timeline or under Advanced; a refusal after a write inside a transaction throws.**

## 2. Surfaces after M45
Overview = `PageShell` → `ProjectBrief` (two rows of tiles) → `SupervisorRequest` input → `SupervisorTimeline` (lanes as filters, DECISION REQUIRED pinned first when non-empty) → `Team` strip (worker rows, disclosure) → `Advanced ▾` (Graph, Office, Analytics, the old live-events river link). Tasks tab = board with the new rows. Settings keeps the goal editor and history (the full document). CLI `request-change`. Domain: `userSupervisorStatus`, `laneFor`, `composeGoal`. Control: `requestChange`. Migration: `GoalVersion.request`.

## 3. Out of scope
Staffing requests (M47/M50), memory ("I already know…", M49), three-tier cost (M51), external-origin labels (M54), a stored model-written interpretation sentence (rejected: the delta is the interpretation), Office redesign, Cursor-specific surfaces.

## 4. Errata — where execution corrects this spec
(appended during execution)

Found while writing the plan (2026-09-11, before Task 1); each is baked into `docs/superpowers/plans/2026-09-10-m45-project-experience.md`. Reasoning with file citations is in the plan's companion notes (session scratchpad); summarised here.

- **E1/E2 (amend R1).** The brief is EIGHT facts (objective, supervisor, work, team, needsYou, latestVerified, cost, recentChanges); `cost` gains `spentUsd` from `workspaceSpend()` — the page shows one total (the header's) plus the two-part measured/unmeasured breakdown, never a second total.
- **E3 (amends R1).** `userSupervisorStatus` takes a fact bag (`{ enabled, halted, pendingDecisions, unansweredQuestions, working, watching… }`), not `SupervisorReport` — `report.supervisor.pending` is windowed (`DECISION_WINDOW_MS`) and would under-count an open proposal; WATCHING gets an explicit rule (enabled, nothing pending, no active work).
- **E4/E5/E26 (amend R2).** `task.created`/`task.cancelled` are written only by planning/re-plan runs (`actor: 'slave'`) — lanes classify on the envelope's `actor`, not `goalVersion > 1` (a first plan's tasks are a plan change too). The domain exports no runtime event-type list, so `LANE_BY_TYPE` is an exhaustive `Record` over the 49 domain event types (count asserted; an addition fails to compile). **E21:** `workspace.replanned` carries task IDs, so the interpretation sentence is the pure `replanSentence(payload, titlesById)` with titles resolved by the read model. **E25:** there is no `supervisor.approved` event — `recentChanges` uses `supervisor.applied` and `supervisor.resolved { outcome }`.
- **E6/E7/E8/E9 (amend R3).** `requestChange` composes INSIDE `setGoal`'s `FOR UPDATE` lock via a shared `writeGoalVersion(textOf)` (composing outside would drop a concurrent edit); `composeGoal(null, request, at)` makes the request the whole goal on a project with no objective; a blank request refuses with a new `invalid_request` kind (three homes); the CLI `request-change` has no `--by` (no principal; `set-goal` has none either).
- **E10/E11 (amend R2/R1).** There is no web unblock route — one is added (`POST /tasks/:id/unblock` → `unblockTask`); there is no web integration verb — the `integrate` needs-you item LINKS to the task on the board (`/w/:id/tasks?task=<id>`).
- **E12.** `ProposalRow`/`DraftEditor` are exported in place from `SupervisorPanel.tsx` (not moved) so its tests stay green.
- **E13/E14/E15/E16/E17 (amend R7/§2 against `gate:m14-fidelity`).** m11-shell touches only layout selectors on Overview (nothing to repoint); `timeline-rule` 88 px is an Activity pin; the live-events river keeps `data-testid="live-events"` and its 340 px under `Advanced ▾`, and m14's `NUMBERS` loop gains a per-row `prepare` hook that opens the disclosure before measuring; the Team strip IS the existing `SlaveCard` grid (six fidelity assertions live on it) — R4's worker disclosure lands on `SlavePanel`; `TopStrip` (`data-testid="strip"`, m14's page marker and halt-clear wait) stays under the brief. **E22:** `SupervisorPanel`, `BlockedPanel` and `MergeQueuePanel` also move under `Advanced ▾` (no removal).
- **E18 (amends R5).** `PageShell` gains a `flush` mode (no gutters) so `/w/:id/*` adoption is pixel-neutral.
- **E19.** Extend `/api/w/:id/overview` (one stream per page) rather than add `/brief` + `/timeline` routes.
- **E20 (amends R1).** The needs-you queue has four SOURCES (blocked tasks; pending decisions — `subjectId` may be a task, a message, a role or the workspace; unanswered questions; un-integrated done on hand-merge), de-duplicated per task; `needsYou(facts)` decides the task-shaped ones.
- **E23 (amends R7).** The m45 gate seeds its own rows (a pending decision, a question to nobody, an un-integrated done task…) like m44's E10, or its negatives are vacuous. **E24:** the optional `request` payload field breaks no consumer (`PAYLOAD_BY_TYPE` gains the optional key).
- **E27 (Task 1 review).** `requestChange` refuses `duplicate_request` when the latest goal version's stored `request` is byte-equal to the new one (a double-submitted "Tell the Supervisor" must not write two versions and arm two re-plan runs); `goal_unchanged` is unreachable from a request (composition always appends). `supervisor.applied` and `supervisor.resolved` are DECISION REQUIRED-lane entries rendered as resolved (muted), so a decision a person took leaves its trace where it was asked. `TimelineSubject` carries `event | decision | question | blocked_task` arms. The Supervisor fact bag's field is `pendingQuestions`.
