# M39 — Supervisor mailbox: answer, re-address, escalate; and the M38 structural backlog

Fifth milestone of the Supervisor sequence (M35 pipeline honesty, M36 messaging and waiting, M37 run context, M38 Supervisor core). Design approved in chat 2026-09-09 (approach A). "Slave" is this project's word for an AI worker.

**Goal.** A question one slave asked another no longer waits on a human by default. The Supervisor reads every pending question, and for each one either answers it itself (immediately when the answer is *sourced* from recorded context, as a draft proposal when it is not), re-addresses it to the slave who can answer, or escalates it to a human — every choice a `SupervisorDecision` row with a rationale, through M38's tiers, cooldown and approval flow. The same milestone closes the four structural items M38's final review left open.

**Why now.** M36 made asking possible and M38 made the Supervisor notice a stale or unanswerable question; both still end in a human typing an answer. The workspace goal, the task text, the asker's own recorded run context and the thread already hold most answers.

## 1. Rules that bind every part
- **Everything M38 §1 says still binds**: a decision is not work; model output never writes (see the one exception below, and its guard); pure domain; single write gate; tiers fixed in code; cost is workspace cost; never a real model call in tests or gates; idempotent and quiet.
- **The one place model text reaches the world is an answer body**, and only through `answerQuestion` after: (a) `neutraliseMarkers`, (b) a length cap `ANSWER_MAX_CHARS = 4_000`, (c) the *sourced* check below deciding whether it goes now or as a draft. The model never chooses the tier.
- **Sourced means verified in code.** The model returns `sources: [{ kind, ref, quote }]`. An answer is *sourced* only if every quote is a verbatim substring of the named source (task title/description, workspace goal, the asker run's recorded `RunContext.prompt`, or a message body in the thread) and at least one source is present. Anything else is an *interpretation*: tier `proposed`, sent only when a human approves (and may edit) the draft.
- **Critical questions never get an automatic answer.** A question is critical when the deterministic lexicon matches its body (`CRITICAL_PATTERNS`: scope change / new requirement, permissions and credentials, secrets and keys, spend and budget, deleting or force-pushing, contacting anyone outside the workspace) OR the model marks `critical: true`. Either signal suffices; both are recorded. Critical → `escalate_to_human` only.
- **Re-addressing is a real verb** (`reassignQuestion`), routine only when the target already holds the recipient role (or the question was slave-addressed and the target is idle and holds any role the asker's task requires); otherwise the existing M38 `set_runtime_roles` proposal comes first and the re-address follows on a later pass.
- **Two model calls per question at most** (choose, then answer), each under `SUPERVISOR_PER_CALL_CAP_USD`, both counted by the per-tick cap and `modelCalled`.
- Refusals inside a Prisma transaction throw; verbs return `ok()/err()`; `refusalText` covers every new kind; the web completeness list is extended; migrations are real directories with `migrate diff` empty; vocabulary `slave`; one vitest at a time; `web:build` last.

## 2. Data model
- `SupervisorDecision` gains `draft Json?` — for `answer_question` decisions: `{ body, sources, critical: { lexicon: string[]; model: boolean }, confidence: 'sourced' | 'interpretation' }` written at decision time, the thing a human approves or edits. No other schema change for the mailbox.
- `SlaveMessage` gains nothing. A Supervisor answer is a normal `answer` row via `answerQuestion` with `answeredBy: 'supervisor'`, envelope actor `system` (or `human` when a human approved the draft; `userId` set). A re-address updates `recipientSlaveId` (and clears `recipientRole`) on the question row and appends `slave.message_reassigned { messageId, from: { role | slaveId }, to: { slaveId }, decisionId }` — one new `EventType`.
- Retention: `SupervisorDecision` rows with `status ∈ {approved, rejected, expired, failed, applied}` and `resolvedAt ?? createdAt` older than `DECISION_RETENTION_MS = 30 days` are deleted by `pruneDecisions(workspaceId, now)` on each supervised tick (bounded `deleteMany`, at most 500 per pass). Pending rows are never pruned. Migration: `20260910100000_m39_mailbox` (the `draft` column + the enum value).

## 3. Domain (`packages/domain/src/supervisor/`)
- `world.ts`: `SupervisorQuestion` gains `body`, `taskId`, `taskTitle`, `senderRunId`, `threadId`, `thread: { messageId, kind, senderSlaveId | null, body, createdAt }[]` (the thread's messages, oldest first, bodies capped at `THREAD_BODY_MAX_CHARS = 2_000` each), `askerRunPrompt: string | null` (the asker run's `RunContext.prompt`, capped at `RUN_PROMPT_MAX_CHARS = 16_000`), `holders: string[]` (slave ids that may answer today). Loader work is Task 3.
- `actions.ts`: `nudge_answer` is REMOVED (M38 said "M39 answers"); added `answer_question { messageId }` and `reassign_question { messageId; toSlaveId }`.
- `candidates.ts`: for `waiting_stale` (a holder exists): `answer_question`, `reassign_question` to an idle holder when the addressed one is busy, `escalate_to_human`, `no_action`. For `unanswerable_question` (no holder): `answer_question`, `reassign_question` to the best non-busy slave whose title/roles match the recipient role — only when that slave holds the role (else the M38 `set_runtime_roles` staffing candidates, unchanged), `escalate_to_human`, `no_action`.
- `policy.ts`: `tierOf`: `answer_question` → `proposed` in the catalogue (the safe default a rules-only pass would store); `reassign_question` → `applied` when the target holds the role, else `proposed`; halted → every action `proposed` as in M38. New pure `answerTier({ sourced, critical, halted }): Tier` — `escalated` when critical, `proposed` when halted or not sourced, else `applied` — is the only place an `answer_question` decision's FINAL tier comes from (§5). `chooseByRules` unchanged: it prefers the single routine candidate, so with no model wired it never picks `answer_question` (tier `proposed`) over a routine `reassign_question`.
- `critical.ts`: `CRITICAL_PATTERNS: readonly { key: string; pattern: RegExp }[]` (case-insensitive; e.g. `scope`: /\b(out of scope|change the (scope|requirements?)|new requirement)\b/, `permissions`: /\b(permission|credential|access token|sudo|admin)\b/, `secrets`: /\b(secret|api[ _-]?key|password|private key)\b/, `spend`: /\b(budget|cost|spend|pay)\b/, `destructive`: /\b(delete|drop|force[- ]push|rm -rf|wipe)\b/, `external`: /\b(email|contact|customer|client)\b/) and `criticalMatches(body): string[]`.
- `answerPrompt.ts`: `buildAnswerPrompt({ question, world })` — the question, the asker's task title/description, the workspace goal, the thread, the asker run's recorded prompt (all through `neutraliseMarkers`), the roster; asks for JSON `{ "answer": string, "sources": [{ "kind": "task" | "goal" | "run_context" | "message", "ref": string, "quote": string }], "critical": boolean }` and contains the literal `"sources"` (the fake CLI's arm). `parseAnswer(text)` → zod; `null` on anything invalid; `answer` trimmed, ≤ `ANSWER_MAX_CHARS`, `sources` ≤ 8, quotes ≤ 300 chars.
- `sourced.ts`: `verifySources(sources, question, world): { verified: Source[]; rejected: { source; reason }[] }` — quote must be a verbatim substring (after whitespace normalisation) of the named source; `ref` for `message` is a message id in the thread, for `task` the question's task id, for `goal` the workspace id, for `run_context` the sender run id. `isSourced = verified.length > 0 && rejected.length === 0`.
- `report.ts`: `summarise` gains `mailbox: { pendingQuestions, answeredBySupervisor24h, draftsAwaiting }` (computed from `world.questions` and `world.decisions`).

## 4. Control (`packages/control/src/`)
- `messaging.ts`: `answerQuestion` gains `origin?: 'human' | 'system'` (envelope actor) and accepts `answeredBy: 'supervisor'`; new `reassignQuestion(messageId, toSlaveId, actor, origin)`: refuses `message_not_found`, `message_not_question`, `question_answered`, `slave_not_found`, `reassign_not_permitted` (target holds neither the recipient role nor, for a slave-addressed question, any role the asker's task requires); updates the row and appends `slave.message_reassigned`.
- `supervisor.ts`: `recordDecision` accepts `draft` and an optional `tier` that overrides the chosen candidate's tier (used only for `answer_question`, with `answerTier`'s result); `carryOut`: `answer_question` → `answerQuestion(messageId, { body: draft.body, answeredBy: 'supervisor', principal }, origin)`; `reassign_question` → `reassignQuestion(...)`. `approveDecision(id, principal, edit?: { body: string })` — for a draft, an optional edited body replaces `draft.body` before applying (recorded on the row as `draft.editedBody`). `pruneDecisions(workspaceId, now)`.
- Delta-union (M38 residual): `carryOut`'s `set_runtime_roles` arm receives the decision's `situation.facts.role` and unions the current set with THAT role only (never the stored array); the stored `roles` stay for display.
- `stats.ts`/`supervise`: `loadSupervisorWorld(workspaceId, now, opts?: { stats?: WorkspaceStatsSnapshot })` reuses a snapshot the tick already loaded; `tick()` passes its own.
- `org.ts` projects list: spend through `workspaceSpend` per project (one `groupBy` over decisions for all projects in one query, not N).
- Refusal kinds: `message_not_question { messageId }`, `question_answered { messageId }`, `reassign_not_permitted { messageId; slaveId; reason }`, `draft_missing { decisionId }`.

## 5. Orchestrator (`apps/orchestrator/src/supervisor.ts`)
For a question situation the pass runs: candidates → if the chosen (by model or rules) action is `answer_question`: second model call with `buildAnswerPrompt` (under the same per-tick cap; if the cap is hit, the situation is decided as `escalate_to_human` by the rules) → `parseAnswer` → `criticalMatches` + model `critical` → `verifySources` → the row is recorded with `tier: answerTier({ sourced, critical, halted })`: critical → `escalated`/pending (no answer sent, the draft kept for the human to see), sourced → `applied` and `answerQuestion` runs, interpretation → `proposed`/pending with the draft. Both calls' costs are recorded (`modelCostUsd` is the sum; `modelCalled` true). When no decider is wired the rules choose `reassign_question` if routine, else `escalate_to_human` — the Supervisor never writes an answer without a model.
`pruneDecisions` runs after `expirePendingDecisions`.

## 6. Web, CLI, gate
- Web: the panel's proposal row for an `answer_question` draft shows the question, the draft body in an editable textarea, the sources (verified ones as quotes with their origin), the critical flags; Approve posts `{ body }` when edited. `POST .../decisions/[id]/approve` body `{ body?: string }`. A `Mailbox` block in the panel: pending questions with who they wait on. Timeline card for `slave.message_reassigned`.
- CLI: `approve-decision --id <id> [--body-file <path>]`; `reassign-question --message <id> --to <slaveId> [--by <name>]`; `supervisor-decisions` prints `draft.confidence` when present.
- Gate `gate:m39-supervisor-mailbox` (real daemon, fake CLI `m36-flow` for the ask + a `"sources"` arm replaying `supervisor-answer.ndjson` whose quote is taken from the fake task's description): stage 1 — a slave asks a question whose answer is in the task description; the recipient role has no holder → `unanswerable_question` → Supervisor answers, row `applied`, `draft.confidence: 'sourced'`, an `answer` message with `answeredBy: 'supervisor'`, the waiting run resumes (`deliverAnswers`) and concludes; stage 2 — a question whose fixture answer cites a quote NOT in any source → row `proposed` with the draft, no answer message; `approve-decision --body-file` with an edited body → answer sent with the edited text, `draft.editedBody` recorded; stage 3 — a question containing "api key" → `escalated`, no answer, `draft.critical.lexicon` names `secrets`; stage 4 — a stale question whose role IS held by a busy slave and another idle holder exists → `reassign_question` applied, `recipientSlaveId` updated, `slave.message_reassigned` event; stage 5 — a resolved decision older than 30 days is pruned, a pending one is not.

## 7. Out of scope
Changing dispatch order for a stale question's holder; thresholds as settings; multi-workspace supervision; answering questions a human asked; the rotating model cursor (E8) and the remaining panel polish.

## 8. Errata — where execution corrects this spec
### Plan writing (2026-09-09)
- **E1 — `Source.ref`.** Required only for `kind: 'message'` (the thread message id); `task`, `goal` and `run_context` are single-valued for a question and `ref` is ignored — a test fixture cannot know a task id.
- **E2 — the lexicon short-circuits.** When `criticalMatches(body)` is non-empty no answer call is made: the decision is `escalated` with `draft: { body: null, sources: [], critical: { lexicon, model: false }, confidence: 'interpretation' }`. The model's `critical` flag is only consulted when an answer call happened.
- **E3 — fake CLI answer arm.** Keys on the literal `"sources"` in the prompt and replays the fixture named by `FAKE_CLAUDE_ANSWER_FIXTURE` (default `supervisor-answer`), so a gate chooses sourced vs unsourced per daemon spawn.
