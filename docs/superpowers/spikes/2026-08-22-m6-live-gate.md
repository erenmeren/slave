# M6 milestone gate: the hand-run against the real CLI

**Date:** 2026-08-22
**Claude Code version:** 2.1.239 · **Branch:** main @ c8faa27 (M6 merged)

Spec §6's gate, both halves. The measured half ran in Task 11 (fake adapter,
`scripts/measure-activity-latency.mjs`: p95 **25–29ms** against the one-second bar, two runs).
This record is the by-eyes half against the **real** `claude`: `npm run demo` seeded workspace
`7af14a68` and ran three real runs ($2.24 total); `npm run web` served the app; the Activity
page was watched in the browser throughout while the API/SSE halves were verified with `curl`.

## Measured checks (real CLI, live load)

- **History + filters + errors:** unfiltered page, `kinds=tool_calls`, and a malformed
  `kinds=nonsense` → 400, all correct while the run streamed; `nextBefore` cursor sane.
- **Intervention liveness:** `POST /pause` from the panel's route while listening on the
  `kinds=interventions`-filtered stream — `run.pause_requested` arrived **9ms** after its `ts`,
  and the whole POST→frame round trip took 399ms including the request itself. Two orders of
  magnitude under the gate's bar, through a filtered stream.
- **Agent+kind-filtered stream:** `agents=<id>&kinds=tool_calls` delivered a matching frame
  with a 34ms gap; nothing off-filter leaked.
- **Sparkline aggregation:** the workspace buckets moved with the real run's tool calls.
- **M5 regression check, live:** the paused saga run was resumed through the web route; the
  daemon claimed and executed the intent and the run completed — the M5 gate's finding 1
  (pause leaving a live child, resume refused) did not recur under kill-on-pause.

## By-eyes checks (operator-confirmed, real browser)

All eight passed clean, including the three the jsdom suite structurally cannot observe:

- Live tail auto-follows at the bottom; per-type card bodies render correctly.
- Scrolling up accumulates the "↓ N new events" badge; clicking re-pins to the bottom.
- **Deep history scroll preserves the reading position across prepends** (the single-writer
  scroll-compensation design, verified in a real layout engine for the first time).
- Refresh opens pinned at the newest event.
- Expanding a card's payload neither jumps the view nor lets the next arrival yank away.
- Filter chips narrow the list live, carry in the URL, and survive refresh; the live stream
  continues under filters; no full-page fade on a filter switch (the Task 10 fix, live).
- The header sparkline pulses; agent cards carry their mini sparkline.

## Findings

None. Every surface behaved to spec on the first pass — the first gate in the M3–M6 series to
close without a gate-fix task. The final whole-branch review's fix wave (filtered-mount refetch,
`from=0` replay, sparkline re-seed, refetch-failure liveness) had already closed the seams this
gate would otherwise have caught, which is the intended division of labour.

## The moral

The by-eyes half still earned its keep: the three scroll behaviours it confirmed are exactly
the ones the test suite pins only by call-and-arguments, because jsdom has no layout engine.
A green suite plus a green gate is two different kinds of evidence, and this milestone needed
both.
